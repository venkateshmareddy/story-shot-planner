| D-004 | 2026-11-27 | Prompts are composed: `SOURCE_RULES` + `CRAFT_PRINCIPLES` + stage base + per-format modifier (`composeInstructions`). | Reuse filmmaking knowledge across formats without duplicating prompt text. | Active (Phase 1) |

| D-006 | 2026-11-27 | Adaptive one-question-at-a-time interview. | D-007 | 2026-11-27 | Every AI refinement is a proposal that needs explicit Apply or Discard; nothing overwrites the story silently. | Filmmaker keeps final creative control. | Active |
| D-008 | 2026-11-27 | Session persistence is browser `localStorage` behind `useSessions()`. A PostgreSQL + Prisma implementation was built in Phase 3 and then removed at the user's request. | Hackathon scope. `useSessions()`'s `SessionStore` interface is the seam for a future database. Supersedes the Phase 3 database decision. | Active |
| D-009 | 2026-11-27 | No authentication or multi-user support in the MVP. | Hackathon scope. | Active |
| D-010 | 2026-11-27 | Tests use the built-in `node:test` runner with no extra dependencies. `tsx` was added for Phase 3 and removed with it. | Zero-dependency testing; mocked model output so tests need no API key. | Superseded by D-019 |
| D-011 | 2026-11-27 | Models: `gpt-6.2-sol` for story work, `gpt-transcribe` for voice. Change only after verifying against the account. | Both verified available via `GET /v1/models`. | Active |
| D-012 | 2026-11-27 | UI is the Studio: session sidebar, conversation panel and editable Story Editor, plus settings and usage views, in the warm cream/terracotta theme. The earlier intake → workflow → studio components were removed. | Confirmed interface; the legacy components were unreferenced after the Studio replaced them. | Active |
| D-013 | 2026-11-27 | Token usage is recorded only from the real `response.usage`; one model call per user action. | Accurate cost tracking; never fabricate usage. | Active |
| D-014 | 2026-11-27 | Outputs are text only: no image, storyboard, animation, video or audio generation, and no budget estimation. | Product scope. | Active |
| D-015 | 2026-11-27 | The plan step enforces that every dialogue line appears verbatim in the source story; refine does not, because the filmmaker is directing the edit. | Prevent invented dialogue while allowing user-directed rewrites. | Superseded by D-017 |
| D-016 | 2026-11-27 | Project agent workspace: root `CLAUDE.md` (imports `AGENTS.md`), auto-loaded `.claude/rules/`, specialist subagents in `.claude/agents/`, on-demand knowledge in `project-agent/`. | Consistent rules and continuity across sessions with small always-loaded context. | Active |
| D-017 | 2026-11-27 | Plan generation uses the project title, all interview answers (including edited ones) and all collected creative details. The AI may write original dialogue; there is no verbatim-dialogue check. Structural validation stays. | User decision: the Studio has no source story text, so the verbatim rule blocked all dialogue. | Active |
| D-018 | 2026-11-27 | Multi-agent Creative Director: a server-side orchestrator (`/api/story/director`) routes each refining-phase request deterministically (keywords, no model call) to only the relevant specialists — Story, Cinematography, Sound, Editing, Continuity — runs them in parallel with minimal context, merges their field-level edits into a proposal that needs Apply, and synthesises one reply (one extra call only when ≥2 specialists ran). No match falls back to the existing refine. | Professional filmmaking intelligence with bounded cost and the filmmaker's approval preserved. | Active (Phase 4) |
| D-019 | 2026-11-27 | `tsx` is a dev-only dependency; tests run with `node --import tsx --test`. | The multi-file agent architecture uses `@/` and relative imports that plain `node --test` can't resolve. No runtime impact. | Active |
| D-020 | 2026-11-27 | Intelligent discovery controller built on the user's 20-category framework: a `StoryContext` (`src/lib/story-context.ts`) covers the 18 creative/production categories with framework priorities; facts record source (filmmaker or AI) and approval; AI suggestions never overwrite filmmaker or approved facts; missing categories and readiness (all critical covered) are computed deterministically. "Stop / Proceed / Generate plan" ends discovery with no model call (client and server); "Skip" and "You decide" are recorded answers. Interview output cap 2,000 tokens. | The AI kept asking after "stop" and ignored most of the framework. | Active |
| D-021 | 2026-11-27 | Reference images are analysed (composition, lighting, angle, colour, setting, mood, shot ideas) via `/api/story/image` with `detail: "low"`; only the text analysis is stored (≤6 per session); the first 4 reach the Camera specialist; file bytes must match the declared type; 4,000,000-byte limit. No image generation. | Phase 5 image understanding with bounded cost and no image storage. | Active — live check pending a valid key |
| D-022 | 2026-11-27 | The final blueprint is assembled deterministically from session data (no AI call) and exported client-side: PDF with `pdf-lib` (standard fonts, WinAnsi text only), Word with `docx`, both loaded on demand. Drafts at any stage; final export needs a plan and the filmmaker's confirmation. | Phase 6 deliverable using real project data; `jspdf` avoided because its optional browser deps break Next builds. | Active |
| D-023 | 2026-11-27 | Revisions that name specific scenes or shots run the refine fallback on only those scenes and splice the result back; other scenes stay untouched. | Revise one scene without regenerating the whole plan. | Active |
| D-024 | 2026-11-27 | Plain-language rule (`PLAIN_LANGUAGE`) in every AI stage and specialist; UI labels simplified; specialist labels Story, Camera, Sound, Editing, Consistency. | User request: wording anyone can understand. | Active |
| D-025 | 2026-11-27 | One runtime identity, `DIRECTOR_PERSONA` (`src/lib/server/prompts.ts`), inherited by every story stage, all five specialists and the synthesis. Two response styles: `DISCOVERY_STYLE` (interview: one short conversational question, optional note/rationale) and `ANALYSIS_STYLE` (everything else: structured, as detailed as the request needs). `PLAIN_LANGUAGE` no longer limits length. | "Concise when asking, detailed when analysing"; the old one-sentence limit truncated professional analysis. | Active |
| D-026 | 2026-11-27 | Discovery guards: `tidyQuestion` keeps one main question plus an optional options follow-up; `isNearDuplicate` (word-set similarity ≥ 0.8) ends discovery instead of re-asking; note and rationale capped at 200 characters. Plan `reviewNotes` start with "Assumption:" or "Suggestion:". | Fewer, better questions; assumptions distinguishable from recommendations. | Active |
| D-027 | 2026-11-27 | The director receives the structured StoryContext and the last 12 resolved proposals (`buildDecisionHistory`); each specialist gets only its relevant categories (≤16 facts with status filmmaker/approved/ai_suggestion, ≤4 open questions, last 6 decisions). Rejected changes are not re-proposed unless asked. Output caps: Story/Camera/Continuity 1,800, Sound/Editing 1,500, synthesis 1,200; ≤5 recommendations per specialist. Replies render as paragraphs, labels and lists (`formatReply`). | Deeper, context-aware specialist analysis that respects the filmmaker's decisions. | Active |
